# Eight Bachelor’s elective topics as a chain of technical decisions

This appendix connects the eight elective lessons, each of which can be read independently. It is **not a new module**, a project assignment or an instruction to set up devices or cloud services. The following designs are fictional learning examples; they illustrate the transitions between theory, technology and operations.

## 1. Eight different questions about the same system {#S1}

| Lesson | Guiding question | Typical misconception |
| --- | --- | --- |
| [M8-L1 – Logic and graphs](M8-L1.md) | Which rules, sets and relationships apply? | A logical expression can replace securing its input data |
| [M8-L2 – Languages and compilers](M8-L2.md) | Which inputs are syntactically and semantically valid? | Valid syntax automatically implies safe semantics |
| [M8-L3 – Operating systems](M8-L3.md) | Which tasks run concurrently, and which locks are used? | More threads automatically mean higher throughput |
| [M9-L1 – HCI/accessibility](M9-L1.md) | Can different people safely carry out the correct steps? | An automated accessibility scan proves good usability |
| [M9-L2 – Statistics](M9-L2.md) | What was measured, for whom and under what conditions? | An overall rate already explains the cause |
| [M9-L3 – Microcontrollers](M9-L3.md) | How can a physical quantity be turned into a reliable measurement? | A 12-bit code width guarantees 12 bits of effective measurement quality |
| [M10-L1 – Networks/security](M10-L1.md) | Where are the trust and communication boundaries? | HTTPS automatically implies correct access permissions |
| [M10-L2 – SQL/data modelling](M10-L2.md) | Which records and aggregations answer the domain question? | `COUNT(*)` counts only actual matches on the right in every LEFT JOIN |

## 2. Practical scenario A: Local media catalogue with an import function {#S2}

A desktop application reads image and video data and displays filters, file sizes and processing status.

- **M8-L1:** A filter condition must be logically complete: `Published OR (Logged in AND Approved)`. If the archive is entirely private, online authorisation checks may not be needed at all; an internal consistency check is still useful.
- **M8-L2:** File metadata or search expressions are processed by a defined parser rather than arbitrary string manipulation. Syntactic validity does not protect against a file reference that is invalid in the application domain.
- **M8-L3/M9-L1:** A background thread imports files; the interface remains usable and indicates cancellation. At the same time, cancellation must leave the data in a traceable state.
- **M9-L2/M10-L2:** ‘Mean import duration’ is not the same as ‘typical duration’; when a few files are large, the median and distribution are more informative. The database stores each job with its own key so that counts based on joins do not count jobs twice.

**When additional architecture is unnecessary:** A local SQLite file and a manageable background job may be sufficient. An external Kubernetes cluster, remote access and a distributed broker do not initially address any existing requirement here.

## 3. Practical scenario B: Web service with team access {#S3}

Three teams upload files and are allowed to see only their own files. A report shows import duration and success rate.

``` text
Browser / screen reader
        |
        v
User interface with visible permissions (M9-L1)
        |
        v
HTTPS and a valid session (M10-L1)
        |
        v
Server-side object authorisation (M8-L1 + M10-L1)
        |
        +--> structured input / parser (M8-L2)
        |
        +--> task / job management (M8-L3)
        |
        v
Database + unambiguous relationships (M10-L2)
        |
        v
Metrics with defined denominators (M9-L2)
```

Displaying a ‘Download’ button does not constitute authorisation. Even with HTTPS correctly implemented, the API must check **each specific object identifier** to determine which team may access that object. A background job may be delivered more than once; its intended effect on the application domain must be protected accordingly. A report must not inadvertently count tag assignments instead of files.

**Worked example:** Two teams process 90 and 10 jobs respectively. Assume their mean processing times are 1 s and 10 s. The job-weighted mean is $\frac{90\times1+10\times10}{100}=1{,}9\,\mathrm{s}$; the unweighted mean of the two team averages is 5.5 s. Both figures are correct only for their respective questions. Comparing teams also requires jobs of similar difficulty; otherwise, the job mix distorts the assessment.

## 4. Practical scenario C: Building sensor with a local gateway {#S4}

A sensor supplies digital codes to a microcontroller. A gateway manages temperature and humidity measurements.

``` text
Physical sensor -> ADC -> Microcontroller
                                  |
                             local gateway
                                  |
                           secure transmission
                                  |
                          measurement database
                                  |
                          accessible display
```

**M9-L3:** A 12-bit ADC provides 4096 codes; for an idealised 0–3.3 V input, one step corresponds to approximately 0.806 mV. This does **not** mean that the temperature reading is accurate to 0.806 mV. Sensor errors, calibration and noise introduce separate uncertainties.

**M8-L3/M10-L1:** Measurement, local control and network transmission have different timing and trust requirements. An internet outage must not indiscriminately block a locally safety-critical protective function. Device identities and a secure update mechanism are more important than making the cloud connection as complex as possible.

**M9-L2/M10-L2:** Missing measurements remain missing. If they are simply set to zero in a chart, an apparent sudden drop in temperature may result. Each record should contain the measurement time, device, unit and quality status. Daily averages should be interpreted only when data coverage is sufficient for the domain in question.

## 5. A chain of decisions for practical work {#S5}

1.  **Define the domain question:** What counts as success or failure? (M8-L1)
2.  **Describe the data and input contract:** What is accepted and what is rejected? (M8-L2)
3.  **Identify states and shared resources:** Where can race conditions occur? (M8-L3)
4.  **Design an accessible user journey:** Can people identify and correct errors? (M9-L1)
5.  **Define the measurement and denominator:** Which data could distort the conclusion? (M9-L2)
6.  **Consider device and measurement limits:** Which physical uncertainties arise? (M9-L3)
7.  **Secure trust boundaries:** Who may perform which action on which data? (M10-L1)
8.  **Check the data model and analysis:** Is the intended set of records actually being counted? (M10-L2)

The eight topics do not constitute a strictly linear implementation method: in real projects, these questions influence one another. A convincing architectural design answers all **relevant** questions in appropriate depth and avoids technology that meets no specific need.
